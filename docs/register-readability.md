# 寄存器可读率实测

> 用 `smaliscope audit` 在 Android 16（模拟器，SDK 36）上实测，并在 Android 14（SDK 34）上复核。
> 复现方式见文末。

## 为什么要量这个

ART 校验「读某个寄存器该用哪个 tag」时，依据的是 dex 调试信息里该 slot **声明**的类型，
而不是当前 `dex_pc` 上它实际持有的类型。d8 会把声明为 `int x` 的参数寄存器复用去存对象，
这时按真实类型读会被拒为 `TYPE_MISMATCH(34)`。

寄存器面板是本项目的头号卖点。所以「在真实的、经过混淆的发布包上，这块面板还能剩下多少内容」
是唯一一个能决定产品成不成立的未知数。

## 结论

**产品成立。局部寄存器在所有构建配置下都 100% 可读；最坏情况的总可读率约 96%。**

| 构建方式 | 总可读率 | 参数寄存器 `pN` | 局部寄存器 `vN` |
|---|---|---|---|
| `javac -g`（完整局部变量表） | **100 %** | 100 % | 100 % |
| `javac -g:none`（完全无调试信息） | **100 %** | 100 % | 100 % |
| `javac -g:lines,source`（**javac 默认**，典型 release） | **95.1 %** | 90.1 % | 100 % |
| 上者再过 R8 `--release`（近似真实发布包） | **96.3 %** | 92.4 % | 100 % |

样本：`Calc` 的三个方法逐指令走完，合计 546–617 个「寄存器 × 停留点」观测。

**跨版本复核（Android 14 / SDK 34）**：同样的 `-g` 变体是 **99.7%**（Android 16 上是 100%），
差的 2 个是局部寄存器 `v2` 上的 `INVALID_SLOT(35)`——与参数复用无关的另一种失败，
量级极小。结论不变，但说明这些数字对 Android 版本有轻微敏感性，
换设备后值得用 `audit` 重新量一遍。

## 三个值得记住的事实

**一、局部寄存器 `vN` 从来没有读不出来过。** 这是本次审计最想知道的答案。
`.local` 调试信息缺失并不影响它们——ART 没有声明类型可以拿来否决，就直接放行了。

**二、失败 100% 集中在被复用的参数寄存器上。** 四种配置下，所有失败样本无一例外都是
`p1` / `p2`，且都发生在 d8 把某个声明为 `int` 的参数寄存器改用来存对象之后的那几条指令上。
方法一旦不复用参数寄存器（`compute`、`arraySum`），可读率就是 100%。

**三、反直觉的一点：完全没有调试信息，反而比「只有行号」更好读。**

```
-g          → 有作用域的局部变量表，声明类型精确  → 100%
-g:none     → 没有任何声明类型可供校验，全部放行  → 100%
-g:lines    → 有 debug_info_item（因为要存行号），
              于是参数名/类型也被一并写入，覆盖整个方法  → 参数复用处失败
```

而 `-g:lines,source` 正是 **javac 的默认值**，也是绝大多数 release 构建的选择
（保留行号是为了崩溃栈可读）。所以最常见的发布配置恰好落在最差的那一档。

## 对产品的影响

不需要动 ROADMAP 里预留的备选方案（改按声明类型读、或把面板定位从「看值」退到「看类型」）。
当前做法已经是对的：

- 读不出来时**明确写出原因**（「该寄存器被复用，类型与声明不符，暂不可读」），
  而不是显示 0 或空白。给 agent 的 MCP 文本里也带着这句话——
  模型把「不可读」当成「值是 0」会让后续推理全错。
- 静态类型推导判定「此处没有有效值」（未初始化 / 类型冲突）的寄存器不计入可读率，
  那类情况本来就没有值可读，不是失败。

## 复现

```bash
# 四种变体
for v in debug lines nodebug r8; do ./testapp/build.sh $v; done

# 逐个装上并审计（换变体后要清掉 APK 缓存，否则会复用旧的解析结果）
adb install -r testapp/build/smaliscope-test-lines.apk
rm -rf ~/.smaliscope/apks
./build/install/smaliscope/bin/smaliscope audit com.smaliscope.testapp Calc
./build/install/smaliscope/bin/smaliscope audit com.smaliscope.testapp Point '<init>'
```

`audit` 的做法是在方法入口下断点，逐条单步走完整个方法，
在每个停留位置记录每个寄存器的三种状态：没尝试读（静态分析就说此处无有效值）、
读到了、尝试了但被拒。只有第三种算失败。
